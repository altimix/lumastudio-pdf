# 証明書によるPDF電子署名

LumaStudio PDFのデスクトップ版では、利用者が用意した **P12 / PFX（PKCS#12）証明書と秘密鍵**を使い、編集済みPDFに電子署名を追加できます。印影画像は見た目の押印、証明書署名は文書の改変を検出できる暗号学的な署名として、それぞれ別の機能です。

## 利用の流れ

1. 文字の記入や押印など、PDFの編集を終えます。
2. 電子署名の画面からP12 / PFXを選び、パスワードを入力します。
3. 証明書の所有者、発行者、有効期間、SHA-256フィンガープリントを確認します。
4. 必要に応じて署名の理由と場所を入力し、署名付きPDFを別ファイルに保存します。

署名後に内容を変更すると署名の検証に失敗します。編集が必要な場合は、署名前のPDFを編集し直してから署名してください。このMVPは既存の署名が付いたPDFへの追記署名・複数人署名には対応していません。

## 対応範囲

- P12 / PFXファイルは2MBまで、PDFは100MBまで。
- RSA 2048ビット以上の鍵に対応します。EC証明書、ICカード、OS証明書ストア、リモート署名サービスには未対応です。
- 1つの秘密鍵と、それに対応する署名用証明書を使用します。P12に含まれる中間証明書も署名に含めます。
- 秘密鍵と証明書の対応、秘密鍵による実際の署名検証、有効期間、指定された鍵用途を確認します。期限切れや有効期間前、認証局用の証明書は拒否します。
- SHA-256 / RSAによるCMS（PKCS#7）Detached署名をPDFの`/ByteRange`と`/Contents`に保存します。`/SubFilter`は`adbe.pkcs7.detached`です。実装には[@signpdfの公式ライブラリー](https://github.com/vbuch/node-signpdf)と[node-forge](https://github.com/digitalbazaar/forge)を使用しています。
- 署名の表示欄は不可視です。印鑑などの見た目は署名前の編集機能で配置し、証明書署名はPDFビューアーの署名パネルで確認します。

## 信頼性・時刻について

**署名の暗号学的な検証と、証明書の発行者への信頼は別の確認です。** 自己署名証明書でも改変の検出はできますが、受取人のAdobe Acrobat等では発行者を信頼できない旨が表示される場合があります。アプリで確認できる「自己署名ではない」という情報も、公的な認証や信頼された発行者であることを保証しません。受取人側の証明書チェーン・信頼設定によって扱いが変わります。[Adobe公式：デジタル署名の検証](https://helpx.adobe.com/acrobat/desktop/e-sign-documents/manage-digital-signatures/validate-digital-sign.html)

このMVPはOCSP / CRLでの失効確認、認証局へのオンライン照会、TSA（時刻認証局）のタイムスタンプ、PAdES-LT / LTAなどの長期検証情報の埋め込みには対応していません。記録される署名日時は端末の時刻です。自己署名証明書を利用者本人に代わって自動発行する機能もありません。

## 秘密情報の扱い

証明書ファイル、秘密鍵、パスワード、署名対象PDFをOpenAIなどの外部サービスへ送信しません。秘密鍵の処理はElectronのメインプロセス側で実行し、証明書・パスワードを設定ファイル、ブラウザー保存領域、ログに保存しません。署名用の一時的なPKCS#12データはメモリ内だけで扱い、バッファーを使用後に消去します。ただしJavaScript処理系に残る文字列など、プロセスメモリ全体の完全な消去を保証するものではありません。

## 検証方法

`server/signature.test.ts`では、実在の利用者とは無関係な`LumaStudio TEST ONLY`証明書をテストのメモリ内だけに生成します。生成したPDFについて、PDFのByteRangeから再計算したSHA-256とCMS内のmessageDigestが一致すること、Nodeの暗号ライブラリーでCMS署名が正しいことを独立して検証します。

さらにPDF本文の1バイト改変、CMS署名の改変、署名の範囲外へのデータ追記を検出し、期限切れ・鍵の不一致・誤ったパスワード・既存署名付きPDFの拒否を確認します。これらのテストはAdobe Acrobatでの信頼表示、実際の利用者証明書、Windows/macOSそれぞれの証明書運用を実機確認したことを意味しません。

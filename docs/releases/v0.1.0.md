# LumaStudio PDF v0.1.0 試用版

届いた PDF に名前・住所・日付・口座情報を記入し、印鑑を押して返送するための Windows・Mac アプリです。最初の MVP として、編集・保存・押印・電子署名の操作を試せます。

**このリリースは試用版です。Windows の発行元によるコード署名、Mac の Developer ID 署名・Apple 公証はまだありません。** Mac はアドホック署名でパッケージの整合性を検査しますが、発行元の本人確認を保証するものではありません。

## ダウンロードと起動

| 環境 | 選ぶファイル | 使い方 |
| --- | --- | --- |
| Windows 64 ビット | `LumaStudio-PDF-0.1.0-windows-x64-setup.exe` | インストーラーを起動し、案内に沿ってインストールする |
| Windows 64 ビット・インストール不要 | `LumaStudio-PDF-0.1.0-windows-x64-portable.exe` | 自分のフォルダーへ保存して起動する |
| Mac・Apple Silicon（M1 以降） | `LumaStudio-PDF-0.1.0-macos-arm64.dmg` | DMG を開き、アプリを「アプリケーション」へ移動する |
| Mac・Intel | `LumaStudio-PDF-0.1.0-macos-x64.dmg` | DMG を開き、アプリを「アプリケーション」へ移動する |

Mac の ZIP 版も同梱しています。ZIP を展開した場合も `LumaStudio PDF.app` を「アプリケーション」へ移動します。Mac の種類は Apple メニューの「この Mac について」で「チップ」または「プロセッサ」を確認してください。Node.js のインストールは不要です。

ダウンロード元はこのリポジトリの Release に限定し、必要に応じて `SHA256SUMS.txt` とファイルのハッシュを照合してください。

Macで開発元を確認できない旨の警告が出た場合は、警告を閉じて **システム設定 → プライバシーとセキュリティ** を開きます。LumaStudio PDF の項目にある **このまま開く** から、画面に沿ってそのアプリを許可します。項目は起動を試してから約1時間表示されます。DMG・ZIP内とReleaseの `README-Mac.txt` に、初めて使う方に向けた手順を同梱しました。[Apple公式の手順](https://support.apple.com/ja-jp/guide/mac-help/mh40616/mac)

この配布方法は、既存の [LumaStudio動画編集アプリのMac版](https://github.com/altimix/LumaStudio/blob/main/README-Mac.txt) と同様に、アドホック署名とアプリごとの初回許可を使います。許可画面を実際のMacで確認した結果ではなく、すべての端末で警告なしに開けることを保証するものでもありません。「破損している」「コンピュータに損害を与える」等の警告や、組織管理のMacで許可できない場合は、警告を控えて開発者または管理者へ相談してください。

## 今回できること

- PDF へ日本語・日付・チェック・画像を記入し、位置やサイズを修正する。
- 印影画像の背景を透過して登録し、個人印・会社印を切り替えて押す。
- 複数の PDF を結合し、サムネイルのドラッグでページを並べ替える。
- ページを右クリックして削除・1ページだけの保存をする。ページ操作ボタンで回転する。
- 「元に戻す」「やり直す」で修正する。
- `.lumapdf` の作業データを保存し、後日、文字や印鑑を選んで編集を再開する。
- AI が登録情報から記入・押印の候補を作り、利用者が確認・採用して修正する。
- 証明書の取得方法・対応条件の案内を読み、利用者が所有する P12/PFX 証明書で「署名して保存」する。
- 記入済み PDF を別名保存し、OS の印刷画面から印刷する。

最初は「サンプルの書類で試す」で操作を確認してください。相手へ送るときは「PDF を保存」、後日の修正用にはあわせて「作業データを保存」を使います。

## AI と電子署名について

基本の PDF 編集に API キーは不要です。AI を使う場合は、上部の「AI設定」で自分の OpenAI API キーを登録します。キーはOSの保管機能で暗号化して端末に保存します。AI を実行したときだけ、ページ画像と登録情報を OpenAI へ送ります。配布ファイルに開発者の API キー、プロフィール、印鑑、署名証明書は含みません。

印鑑画像を押す機能と電子署名は別の機能です。証明書署名には、利用者が所有する **秘密鍵を含む RSA 2048 ビット以上の P12/PFX** とパスワードが必要です。購入前にファイル形式と PDF 署名への適合性を提供元へ確認してください。USB トークン・IC カード・クラウド型で秘密鍵を書き出せない証明書は、この MVP では使用できません。

署名後の改変を検出する仕組みを備えていますが、相手が署名者を信頼できるかは証明書と受取側の検証に依存します。自己署名のテスト証明書は本人確認の代わりにはなりません。タイムスタンプ、失効情報の取得、長期検証情報の埋め込み、追記署名は未対応です。

## 検証範囲と制限

リリースのワークフローは Windows・macOS で単体テスト、型検査、ブラウザー操作、パッケージ作成を実行します。パッケージの起動とサンプル PDF 表示は GitHub の各 OS 環境とホストの CPU で確認します。Mac の両アーキテクチャの配布ZIPを実際に展開し、署名とリソースの整合性、改変したテスト用コピーの拒否、起動案内の同梱を検査します。利用者の Mac 実機での初回許可、実プリンター出力、OS の印刷取り込み、実際の証明書の受取側での信頼表示は別途確認が必要です。

ほかのアプリから印刷して取り込む Windows の専用プリンターと Mac の PDF サービスは、任意のセットアップです。自動でプリンターや OS 設定を変更しません。手順は配布アプリに同梱する `docs/printing.md` を参照してください。Windows の固定ファイル受信方式は 1 件ずつ取り込みを待つ必要があります。

既存本文の直接書き換え、OCR、パスワード付き PDF、XFA は未対応です。追加した文字は完成 PDF では画像となり、検索・選択できません。署名済み PDF は保護のため閲覧専用です。

開発の手順と次回以降のリリース方法は `docs/development.md` に記載しています。
